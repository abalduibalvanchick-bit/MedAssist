# Журнал изменений базы знаний MedAssist

## v2.0 — схема v2 (в работе)

### Этап 1. Схема и мини-язык условий
- Добавлен единый файл схемы `kb/_schema/schema.yaml`: домены, категории, папки,
  перечисления, поля метаданных, типы связей с обратными парами, параметры и факты
  пациента, мини-язык условий, машиночитаемый слой по категориям, формат правил.
- Добавлен `src/schema.py` — загрузчик схемы с самопроверкой согласованности.
- Добавлен `src/conditions.py` — интерпретатор условий: статическая проверка,
  трёхзначная оценка (true/false/unknown), трассировка, сбор ссылок, описание на русском.
- `src/config.py` читает структуру из схемы; константы v1 сохранены для совместимости.
- Валидатор переписан: карточки v1 проверяются в режиме совместимости, карточки v2 — строго
  (инвариант ID/домен/папка/файл, перечисления, категории связей, машиночитаемый слой,
  условия, правила `kb/rules`, симметрия связей, качественные показатели).
- Загрузчик материализует обратные связи (`Linker.get_inverse_cards`); поле `related`
  в v2 вычисляется из `relations`.
- Документация `docs/schema.md`, `docs/metadata_schema.md`, `docs/link_types.md`,
  `docs/conditions.md` генерируется скриптом `scripts/generate_docs.py`.
- Тесты: 68 (было 12).

### Решения, принятые на этапе 1
- Коды доменов: `diag`, `pharm`, `prot`, `glb`; папки `kb/<domain>/` совпадают с кодами.
- Поле `related` удалено из схемы v2, связи только через `relations`.
- Знания решателя (условия, правила, шкалы) хранятся в YAML-блоке карточки и в `kb/rules/`,
  а не в коде.
- Пустой `medical_reviewer` запрещён; для учебного проекта используется значение
  «модельная верификация (учебный проект)».
