# Журнал изменений базы знаний MedAssist

## v2.0 — схема v2 (в работе)

### Этап 1. Схема и мини-язык условий
- Добавлен единый файл схемы `kb/_schema/schema.yaml`: домены, категории, папки,
  перечисления, поля метаданных, типы связей с обратными парами, параметры и факты
  пациента, мини-язык условий, машиночитаемый слой по категориям, формат правил.
- Добавлен `src/schema.py` — загрузчик схемы с самопроверкой согласованности.
- Добавлен `src/conditions.py` — интерпретатор условий: статическая проверка,
  трёхзначная оценка (true/false/unknown), трассировка, сбор ссылок, описание на русском.
- `src/config.py` читает структуру из схемы; константы v1 сохранены для совместимости.
- Валидатор переписан: карточки v1 проверяются в режиме совместимости, карточки v2 — строго
  (инвариант ID/домен/папка/файл, перечисления, категории связей, машиночитаемый слой,
  условия, правила `kb/rules`, симметрия связей, качественные показатели).
- Загрузчик материализует обратные связи (`Linker.get_inverse_cards`); поле `related`
  в v2 вычисляется из `relations`.
- Документация `docs/schema.md`, `docs/metadata_schema.md`, `docs/link_types.md`,
  `docs/conditions.md` генерируется скриптом `scripts/generate_docs.py`.
- Тесты: 68 (было 12).

### Решения, принятые на этапе 1
- Коды доменов: `diag`, `pharm`, `prot`, `glb`; папки `kb/<domain>/` совпадают с кодами.
- Поле `related` удалено из схемы v2, связи только через `relations`.
- Знания решателя (условия, правила, шкалы) хранятся в YAML-блоке карточки и в `kb/rules/`,
  а не в коде.
- Пустой `medical_reviewer` запрещён; для учебного проекта используется значение
  «модельная верификация (учебный проект)».

### Этап 2. Миграция карточек v1 → v2
- `scripts/migrate_v1_to_v2.py`: детерминированный, идемпотентный мигратор с сухим прогоном;
  отчёт `docs/migration_v1_to_v2.md`.
- Все 125 карточек переведены на схему v2. Папки доменов: `diagnostics → diag`, `therapy → pharm`,
  `protocols → prot`, `global → glb`. Файлы алгоритмов неотложной помощи переименованы
  в `prot_emergency_p_*` (инвариант «префикс файла = domain_category_»).
- 338 связей получили канонические типы v2 с учётом категорий источника и цели;
  61 цель перенесена из `related` в `relations`; поле `related` удалено.
- `medical_reviewer` у всех карточек заменён на «модельная верификация (учебный проект)»,
  включая условные ФИО из примеров ТЗ. 11 карточек `approved` переведены в `medical_review`
  до заполнения машиночитаемого слоя. У четырёх карточек обследований исправлен
  `evidence_level: I` (значение класса рекомендаций).
- Схема связей расширена по результатам инвентаризации реальных связей: добавлены
  `considers/considered_in` (дифдиагностика) и `uses_exam/exam_used_in`; расширены допустимые
  категории для маршрутизации, шкал, неотложных алгоритмов и наблюдения.
- Проверка симметрии заменена проверкой противоречий: ошибкой считается только случай,
  когда обе карточки утверждают одно и то же направленное отношение друг о друге.
- `scripts/generate_indices.py`: индексы `index.md` во всех папках, каталоги `indices/<domain>_catalog.md`,
  `indices/statistics.md`, `PROJECT_TREE.txt` генерируются из карточек.
- CLI `--related` показывает и материализованные обратные связи.
- README и `docs/` обновлены под схему v2. Тестов: 74.
- Итог валидации в строгом режиме: 0 ошибок, 20 предупреждений
  (16 карточек с одним источником, 4 заглушки).

### Этап 3. Наполнение базы знаний
- Машиночитаемый слой заполнен у всех 166 карточек: признаки и синонимы симптомов, результаты
  обследований, взвешенная клиническая картина заболеваний, условия красных флагов, критерии
  неотложных состояний, ветви дифференциальной диагностики, параметры и интерпретация шкал,
  таблицы решений маршрутизации, фазы и препараты неотложных алгоритмов, шаги и ветвления
  протоколов, планы наблюдения, скрининги, пункты чек-листов, тревожные признаки памяток,
  представители и противопоказания групп препаратов, линии терапевтических схем.
- Новые карточки (41): очаговый неврологический дефицит, тропонин, пульсоксиметрия;
  глобальный домен — 5 профилей пациентов, 3 дисклеймера, 30 глоссарных статей.
- Четыре заглушки фармгрупп (БРА, БКК, тиазидные диуретики, НПВС) дописаны до полных карточек.
- Источники дополнены: у всех карточек не менее двух.
- `kb/rules/`: 56 продукционных правил в пяти файлах — границы применимости (glb), диагностические
  гипотезы и первичное обследование (diag), запрос недостающих данных, сквозная маршрутизация (prot),
  фармакологическая безопасность (pharm).
- Статус `approved` означает: машиночитаемый слой заполнен, не менее двух источников, валидатор
  не выдаёт замечаний; медицинская проверка — модельная (учебный проект). Таких карточек 166 из 166.
- Схема: атрибут `implies` у ссылок слоя; метаатом `known` для правил уточнения; действие `warn`;
  `points_from` для опросников; факты анамнеза и противопоказаний, параметры шкал; скрининг без
  обязательных методов (программы вакцинации).
- Валидатор: отражение ссылок слоя в графе связей, полнота и непересечение диапазонов шкал,
  неизвестные поля карточки, ссылки из условий при поиске сирот, пороги длины по категориям.
- Инструменты: `src/card_writer.py`, `src/machine_refs.py`, `scripts/apply_patch.py`,
  `scripts/sync_relations.py`.
- Тестов: 92. Итог валидации: 166 карточек, 56 правил, 0 ошибок, 0 предупреждений, 0 заглушек, 0 сирот.
