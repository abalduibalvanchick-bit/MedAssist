# Правила именования (схема v2)

Формальные шаблоны заданы в `kb/_schema/schema.yaml` (раздел `identifiers`) и проверяются валидатором.

## Идентификаторы карточек

`DOMAIN-CATEGORY-NNN`: префикс домена (`DIAG`, `PHARM`, `PROT`, `GLB`), код категории в верхнем
регистре, трёхзначный номер. Примеры: `DIAG-SYMPTOM-002`, `PHARM-DRUGCLASS-009`, `PROT-EMERGENCY_P-001`,
`GLB-PROFILE-002`.

Номера уникальны внутри пары (домен, категория). Разрывы в нумерации допустимы и сохранены
при миграции со схемы v1, чтобы не менять идентификаторы, на которые уже есть ссылки
(например, `PHARM-DRUG-020`). Новые карточки получают следующий свободный номер.

## Имена файлов

`<domain>_<category>_<краткое_имя>.md`, только `[a-z0-9_]`. Файл лежит в `kb/<domain>/<папка категории>/`.
Пример: `kb/prot/emergency/prot_emergency_p_hypertensive_crisis.md`.

## Идентификаторы правил

`RULE-DOMAIN-NNN`, например `RULE-DIAG-001`. Правила хранятся в `kb/rules/*.yaml`.

## Коды признаков симптомов

`<symptom>.<feature>` в нижнем регистре, например `chest_pain.pressing`. Объявляются в поле
`features` карточки симптома и используются в условиях.
