# Справочник и RAG

## Два способа задать вопрос

Во вкладке «Справочник» вводят вопрос по базе. Из блока «Протоколы и наблюдение» кнопка «Источник маршрута» открывает основание уже выбранного решения. Во втором случае сервер получает идентификатор карточки и индекс строки (или `null` для строки по умолчанию), повторно проверяет доступ и берёт объяснение, срок и действия именно этой строки. Общий справочный поиск запускается при вводе нового вопроса. Исходный случай пациента в запрос к модели не включается.

## Запуск

Обычный запуск `python -m src.web` показывает выдержки. Для запуска с моделями установите и запустите локальный Ollama, затем из корня проекта выполните:

```bash
ollama pull qwen2.5:3b
ollama pull bge-m3
python -m src.web --ollama-model qwen2.5:3b --ollama-embed-model bge-m3
```

Параметры независимы. Первый включает отбор целых предложений или строк таблиц. Второй добавляет смысловое ранжирование найденных фрагментов. Веб-сервер использует адрес `127.0.0.1:11434`. Для проверки работающего экземпляра служит команда:

```bash
python scripts/evaluate_reference.py --ollama-model qwen2.5:3b --ollama-embed-model bge-m3
```

Команда завершится с ненулевым кодом, если не получит проверенную цитату или фактический результат ранжирования от запрошенной модели. Первый запуск может потребовать времени на загрузку весов в память.

## Как строится ответ

1. Для текущей роли строится индекс доступных разделов карточек и подписей структурированных полей. Знаки препинания, регистр и окончания слов нормализуются для поиска. Цитаты извлекаются из исходного текста.
2. BM25 оценивает совпадения в тексте раздела. Разреженные TF–IDF-векторы символьных триграмм заголовков сравниваются с запросом по косинусу. Такой поиск помогает при опечатках. Для кандидата, найденного только по триграммам, проверяется сходство каждого значимого слова с заголовком.
3. Результаты объединяются по сумме обратных рангов `1/(60 + ранг)`. С моделью эмбеддингов до 30 лучших кандидатов повторно сравниваются с вопросом по косинусу векторов Ollama. Третий список также участвует в объединении. Порог допуска первого этапа сохраняется. При ошибке эмбеддингов используется локальная выдача.
4. При включённом генераторе Ollama получает вопрос и пронумерованные фрагменты. Ответ проходит проверку номера и дословного совпадения полного предложения, строки или их последовательности. Ошибка вызова или цитирования возвращает исходные выдержки с пояснением. Пустой подтверждённый список модели на свободный вопрос и отсутствие кандидатов дают сообщение о нехватке сведений. Для запрошенной строки маршрута сохраняется возможность прочитать первоисточник.
5. У каждой выдержки есть номер, идентификатор карточки и раздел. Кнопка открывает исходную карточку с библиографией. Эти ссылки подтверждают происхождение текста. Клиническая валидация содержания находится за пределами учебной проверки.

## Проверка поиска

Команда `python scripts/evaluate_reference.py` выполняет один и тот же набор из `tests/reference_cases.yaml` двумя методами. Ранг считается по позиции первого фрагмента ожидаемой карточки. Одна карточка может занимать несколько позиций разными разделами. Набор включает известные контрольные вопросы, опечатки, четыре роли, запросы вне базы и запрос без предмета. Это регрессионный набор разработчика. Результаты локального прогона без моделей приведены ниже.
