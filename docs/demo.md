# Демонстрация и результаты проверки MedAssist

## Запуск

Команды ниже выполняются из корня проекта после установки зависимостей из
`requirements.txt`.

```bash
python -m src.web
python main.py --validate
python -m pytest -q
python scripts/run_solver_cases.py
python scripts/benchmark_solver.py
python scripts/evaluate_reference.py
```

Откройте `http://127.0.0.1:8000`. Для отбора выдержек локальной моделью можно
добавить `--ollama-model ИМЯ_МОДЕЛИ`, если такая модель уже установлена в
локальном Ollama. Для воспроизводимой демонстрации доступен режим извлечения
фрагментов из карточек.

## Навигация по разбору случая

- В карточке итога показаны срочность, маршрут и срок. Когда решатель использовал
  таблицу маршрутизации, специалист, медперсонал и студент видят фактические
  условия выбранной строки. В «Основаниях маршрутизации» также доступны её полное
  описание и действия.
- Уточнения разделены по назначению. Уточнение о срочности показывается первым.
  Кнопки пересчёта учитывают заполненные поля из всех групп, в том числе свёрнутых.
- Специалист начинает с гипотез и аргументов. Медперсонал видит уже внесённые
  измерения и обследования. Студент видит структурированные шаги и может открыть
  правило. У пациента первым остаётся понятный итог, дальше идут уточнения и памятка.
- Кнопки под итогом ведут к разделам результата или обратно к данным пациента.
  «Раскрыть все разделы» показывает все подробности текущего режима.
- В справочнике кнопка «Перейти к каталогу» ведёт к карточкам. Каталог правил
  доступен специалисту и студенту, а состав карточек по ролям определяется базой.

## Сценарии для показа

| Задача | Что сделать | Что проверить |
|---|---|---|
| Диагностика и объяснение | Загрузить «Кашель и неполные данные», разобрать случай, открыть шкалы и ход вывода | При неполном наборе фактов программа выдаёт уточнения и показывает источники выводов |
| Пересчёт | При запросе мочевины в том же примере ввести `8` и пересчитать | Новое измерение учтено, CURB-65 отображает значение 2 |
| Дифференциальная диагностика | Развернуть таблицу ветвей по кашлю | У каждой ветви есть статус. Аргументы и ключевое обследование показаны при наличии в базе |
| Маршрутизация и протокол | Развернуть маршрут и далее протокол того же сценария | Видны срок, признак предварительности и шаги протокола. В режиме специалиста кнопка «Источник маршрута» открывает свидетельство из выбранной строки |
| Терапия и неизвестные данные | Очистить форму, указать учебного пациента 31 года с установленной артериальной гипертензией. Сравнить результат до и после указания факта «Беременность» | У варианта иАПФ статус меняется с «требуется проверка» на «исключён», есть основания из базы |
| Справочник | Задать «Из чего состоит шкала CURB-65?» и открыть ссылку рядом с фрагментом | Источник содержит идентификатор `PROT-SCALE-004` и название раздела |
| Вопрос вне базы | Задать «Рецепт карамельного торта» | Отображается сообщение об отсутствии сведений |

В блоке **Все сценарии** можно выбрать любой случай по группе, названию или
номеру теста. Для проверки одного и того же пациента загрузите сначала пример
**Боль в груди при поступлении · до ЭКГ**, затем **Боль в груди при поступлении ·
с ЭКГ**. Ссылка на публикацию доступна рядом с загруженным сценарием.

Эти случаи предназначены для демонстрации работы программы на учебных данных.

## Материал для главы 3

- **§3.1–3.3. Средства, структура, данные.** Python, PyYAML, HTML, CSS и JavaScript.
  Веб-сервер отдаёт статические файлы и JSON API. Каталог полей собирается из
  схемы и карточек. Решатель использует ту же базу и те же функции в веб-режиме
  и в консоли. Формы не сохраняют случаи на сервере.
- **§3.4. Алгоритмы.** Для работы Соловьёва используйте `facts.py`, `engine.py`,
  `ranking.py`, `differential.py`, `questions.py`, `dialog.py` и `explain.py`.
  Покажите переход от фактов к ветвям, расчёт оценки гипотезы, приоритет
  уточнений и следующее обращение к решателю. Для работы Миронова используйте
  `routing.py`, `protocols.py`, `therapy.py` и `reference.py`. Покажите
  расчёт предварительного маршрута, проверку условий терапии и извлечение источника.
- **§3.5–3.7. Тестирование, измерения, демонстрация.** Используйте
  [отчёт о сценариях](solver_test_report.md), результаты `pytest` и таблицу
  демонстрации выше. В отчёте время по каждому случаю — медиана повторных
  запусков после начальной загрузки. Валидатор проверяет структуру знаний.
- **§3.8–3.9. Ограничения и выводы.** Область решений ограничена содержанием
  учебной базы. Состав полей известен заранее. D4 отложен, вместо него
  используется форма. Справочный режим может показать исходные фрагменты без
  генерации. Совпадение цитаты проверяется программно, медицинское содержание
  базы требует отдельной экспертной оценки для использования вне курса.

Для доклада можно использовать последовательность: постановка задачи, базы
знаний и архитектура, индивидуальные алгоритмы, один сквозной пример, результаты
проверок и ограничения.

Скрипт замера добавляет заведомо несрабатывающие правила к загруженной базе и повторяет один запрос 60 раз при каждом размере. Он измеряет стоимость дополнительного обхода правил при неизменном результате маршрутизации.
