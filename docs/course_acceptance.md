# Готовность учебного решателя MedAssist

Объём относится к пятому семестру и приложению для демонстрации. Пункты проверки взяты из раздела методички «Требования к решателю задач», с. 44–48, и из функциональных требований двух записок. По договорённости диагностический ввод выполняется структурированной формой или JSON/YAML. Свободный текст в справочнике поддерживается.

| Что требовалось проверить или исправить | Результат | Где проверить |
|---|---|---|
| Решение по фактам и правилам из базы, объяснение и повторяемость | Прямой вывод, шкалы, гипотезы, рабочие диагнозы, обследования, уточнения и трасса. Шесть нозологий и связанные неотложные состояния | `src/solver/`, `tests/test_invariants.py`, `tests/test_reachability.py` |
| Видимый итог при неполном, противоречивом или неподдерживаемом вводе | Раздельные исходы с пояснением и следующим шагом. Можно завершить уточнения с неизвестными значениями. Проверяются два одновременно заданных возраста, типы контейнеров замена ранее отрицательного ответа и обработка пустых полей при уточнении | `src/solver/outcome.py`, `facts.py`, `dialog.py`, `tests/test_robustness.py` |
| Выбор и объяснение маршрута, протоколы и ограничения терапии | Учитываются сработавшая строка, строка по умолчанию и неизвестные условия более срочных строк. Ссылка из результата открывает сведения именно выбранной строки. При нескольких основаниях можно открыть каждое | `src/solver/routing.py`, `protocols.py`, `therapy.py`, `tests/test_routing.py`, `tests/test_protocol_execution.py` |
| Четыре режима отображения и доступ к сведениям | Для пациента доступны срочность, маршрут, уточнения и памятки. У специалиста есть таблицы решений и источники, у медперсонала — обследования и наблюдение, у студента — ход вывода. Справочные вопросы и поиск учитывают роль | `src/web/`, `tests/test_completion.py`, `docs/demo.md` |
| Полный цикл RAG с источником и отказом | Два локальных метода поиска, объединение рангов, опциональные нейросетевое ранжирование и отбор цитат. Проверка полных цитат, отсутствие ответа при нехватке оснований, штатный возврат к выдержкам при ошибках сервиса | `src/reference*.py`, `tests/test_reference_rag.py`, [проверка RAG](reference_evaluation.md) |
| Формальные примеры, сравнение с ожидаемым результатом и замеры | 43 типичных, 14 граничных, 6 отрицательных сценариев. В таблице по сценариям показаны фактический маршрут и срок, если они определены. Сценарии задают ожидаемые поля и при необходимости порядок шагов трассы | `tests/cases/`, [протокол 63 сценариев](solver_test_report.md) |
| Оценка эффективности при росте базы | Четыре размера базы правил, 60 повторов на размер, проверка сохранения статуса и маршрута | `scripts/benchmark_solver.py`, таблица ниже |

## Результаты прогона

Среда — Linux x86_64, Python 3.12.14. Валидатор прочитал 191 карточку и 70 правил, ошибок и предупреждений — 0. Автоматические проверки завершились успешно (449 тестов). Сквозной прогон интерфейса на предыдущем коммите проверил 72 сценария в четырёх режимах, раннее завершение уточнений и результат на узком экране. Отдельно проверены переход из случая пневмонии к строке маршрута, открытие первоисточника и смена роли на пациента.

На 63 сценариях при 20 повторах минимум, медиана и максимум индивидуальных медиан составили 0,04, 3,27 и 4,96 мс. Порог из записок — 200 мс для решения после загрузки. Однократная загрузка базы заняла 644 мс. При увеличении числа заведомо несрабатывающих правил получены следующие времена для фиксированного запроса.

| Правил | Медиана, мс | P95, мс |
| ---: | ---: | ---: |
| 70 | 3.46 | 4.32 |
| 140 | 4.01 | 5.50 |
| 280 | 5.26 | 7.51 |
| 560 | 7.83 | 10.35 |

Этот эксперимент измеряет стоимость обхода правил. Время загрузки весов, генерации и HTTP-запросов в замер решателя не входит. Офлайн-поиск проверен на 18 размеченных запросах. Интеграция с Ollama проверена через HTTP с контролируемыми ответами для обоих API, включая отказ и ошибочную цитату. В среде этого прогона сервис с установленными весами отсутствовал. Команда проверки реальной модели приведена в инструкции по RAG.

## Воспроизведение из корня проекта

```bash
python -m pip install -r requirements.txt
python main.py --validate
python -m pytest -q
python scripts/run_solver_cases.py --repeat 20
python scripts/benchmark_solver.py
python scripts/evaluate_reference.py
python -m src.web
```

Оценка подтверждает выполнение учебных сценариев. База ограничена представленными в ней состояниями и прошла модельную верификацию. Клиническая точность на реальных пациентах и статистическая обобщаемость на новые свободные вопросы не измерялись.
